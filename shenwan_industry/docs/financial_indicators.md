# 申万行业指数财务指标计算方法（现阶段口径）

本文档描述 `shenwan_industry` 模块**单日排行**新增的行业财务指标估值列（当前为 **PE**、**PB**、**ROE** 与
**股息率**）的计算方法，是财务指标类算法的**唯一权威文档**——未来新增财务指标（如 PS 等）一律写进本文件
（对应分节），并同步更新 `AGENTS.md` 第 5.1 节的指标清单；**第 11 节为上述 PE/PB 的历史序列化**
（K 线副图估值走势，逐日回放同一公式，非独立指标）。

所有指标均属**项目自建口径**（申万官方指数算法文本不含估值章节，见 `AGENTS.md` 第 8 节）。

## 1. 范围与产出

- 单日榜为时点值（当日市值 ÷ 截至当日已披露最新财报）；**区间榜（官方逐日链式，Web 默认）同样提供全套指标，口径 = 区间末交易日时点值**（涨幅=区间累计、指标=区间末收盘快照，与指数公司估值表"最新收盘日"口径一致；预热线程在编排最开始启动与逐日计算并行、末日市值直接复用逐日循环的 daily_basic 缓存；Web 区间表头注明"财务指标为区间末交易日时点值"）；**静态版区间榜（对照模式）不计算**（保持轻量对照，Web `chain=false` / CLI `RANGE_CHAIN=False`）
- 不区分 `div_kind`（官方价格式 / 分红再投资式）：估值用当日市值与最新财报数据，与除息日涨跌幅口径无关
- 每只行业指数（L1 / L2 / L3）每个指标提供两种**市值口径**（接口/CLI 均返回两列）：
  - **自由流通口径**：以自由流通市值为权重的合成值（等价于"自由流通市值加权的个股总市值口径指标加权调和平均"）
  - **总市值口径**：Σ总市值 / Σ股东值（与新闻/东财常见"行业 XX = Σ总市值 / ΣTTM 利润"同式）
- 净利润同比（第 5 节）与 ROE（第 6 节）均为**随加权方式切换市值口径的双字段**（等权与 PE/PB 一致显示"—"；同比 2026-08-30 改双口径——float=当日自由流通占比分摊/total=全值，原单列无市值维度）；数值**分档显示**（≥100% 用 +x.xx 倍、否则带符号两位小数 %）/类别文本；
  ROE 另随"ROE算法"下拉选择算法（当前仅**加权平均**一档，2026-08-28 新增）
- **股息率（第 7 节，Web 列名"回报率"）为随加权方式切换市值口径的双字段**（等权显示"—"）：数值%（两位小数带 %，不带 + 号不着色），
  随"回报率口径"下拉切换——**TTM估算股息率**（默认选中）/ **TTM估算股息+注销率**（est_bb，2026-08-30 新增，见 7.6）/ **静态股息率**（2026-08-28 新增）
- PE 在两市值口径之外另有**净利润口径四档**——归母/扣非 × TTM/动态（后端一次全部算出、共享同一批
  财务数据零新增请求，口径表 `industry_ranking.PROFIT_BASES`）：
  - **TTM（默认）**：滚动 12 个月（第 3 节）
  - **动态**：最新报告期累计利润 × 4/k 年化（第 3.3 节），与 Tushare `daily_basic` 动态市盈率同法
  接口字段 `pe_{basis}_float`/`pe_{basis}_total`（basis ∈ `attr_ttm`/`attr_dynamic`/`deduct_ttm`/
  `deduct_dynamic`）；**CLI 打印的 PE 两列为默认口径归母-TTM**
- **Web 主表每个指标一列**，随上方"加权方式"切换市值口径（总市值/自由流通 → 对应口径；等权无定义 → 显示"—"）；
  **PE 与净利润同比两列另随"净利润口径"下拉切换四档**（首项归母净利润-TTM 为默认选中，PB 与该下拉无关）；
  成分股子表个股同样四口径切换（`pe_{basis}`/`profit_growth_{basis}`）；CLI 保留每指标两列（一次全打印）
- 显示：无单位/倍率、两位小数；行业股东值合计 ≤ 0 时 PE 显示**"亏损"**、PB 显示**"资不抵债"**（数据为空为"—"）
- **Web 排序**：亏损/资不抵债（null）按最大值参与排序（降序置顶、升序置底），无数据（"—"）恒置底

## 2. 通用约定（各指标共用）

### 2.1 数据源与时点（PIT）

- PE 数据来自 `fina_indicator_vip` **一次批拉同时取多个字段**：`profit_dedt`（扣非净利润）、
  `extra_item`（非经常性损益，自带正负号）与 `bps`（每股净资产），同接口、同报告期、同分页
  （接口明细见 `docs/interface_notes.md`）
- 归母净利润另有**业绩快报（`express_vip`）提前可用源**（见第 3.1 节双源合并规则）；扣非与 bps 无快报源
- PB 数据来自 `balancesheet_vip` 按报告期批拉：**PB 分母 = `total_hldr_eqy_exc_min_int`（归母权益）
  − `oth_eqt_tools`（其他权益工具，合计、已含优先股；子项 `oth_eqt_tools_p_shr` 不可重复扣减）
  = 归属于母公司普通股股东的权益（绝对额元、报告期末时点值）**——与 `bps` 分子**严格同口径**
  （实测 20250407 对账：招行 12260−1804=10456 亿 == bps×当日股本分毫不差；宁波银行 2332−248=2084 亿
  ≈ bps×股本 2082 亿，0.1% 为可转债转股漂移；华能/东航/大唐/深能源等永续债大户隐含股本与当日总股本
  吻合 0.001%），与 Tushare `daily_basic.pb` 及数据商惯例一致（普通股总市值对应普通股股东权益）
- **归母净利润不在该接口**（利润表接口才有归母绝对额，实测本接口请求 `n_income_attr_p` 被静默忽略），
  由恒等式**行内合成**：`归母 = profit_dedt + extra_item`。全市场实测（20250630）：可对齐 6243 只、
  **99.8% 相对误差 <0.1%（P95≈2e-16 浮点精度级）**、有扣非时 extra 缺失率 0%；仅同行两字段齐备
  才算出，否则该行归母=None，**不跨行拼接**（宁缺勿猜，由无财报统计兜底）
- **PIT（消除前视偏差）**：每股取 `ann_date ≤ 计算日 D` 的最大报告期；`ann_date` 缺失按法定披露
  截止日推定（Q1 → 当年 4/30，中报 → 8/31，三季报 → 10/31，年报 → 次年 4/30）
- 报告期窗口 = [D-24 个月, D] 内所有季末（最多 8 期，两池共用 `_fina_period_window`）；按 period 内存缓存
- 市值与涨幅榜同一套当日 `daily_basic` 缓存（含停牌回退值），指标权重与指数权重一致（PB 不再用股本）

### 2.2 数据质量（实测）

- 同股票同报告期存在**重复行**：去重为**字段级**独立取最后一条非空值（实测 601318 20260630 两行
  bps 均有效但值不同 56.7800/56.7751，不能整行丢弃；profit_dedt 存在 NaN 占位行；归母合成在
  字段级去重**之前、按行内值**进行，不跨行拼凑）
- 利润字段为**年初至今累计值**——`profit_dedt` 与合成后的归母均是（实测 601318 五期
  302.59→735.71→1420.57→1437.73→239.12 亿），不是单季值；`bps` 为**报告期末时点值**
  （平安 51.60→56.78 递增），不是累计值
- 接口对 fields 中不存在的字段名**静默忽略**（不报错），取值一律 `getattr` 防御

### 2.3 合成公式（结构统一）

```
自由流通口径 = Σ 自由流通市值 / Σ (股东值 × 自由流通占比)    自由流通占比 = free_mv / total_mv
总市值口径   = Σ 总市值 / Σ 股东值
```

- 每股"股东值"按指标定义：PE = 所选口径净利润（TTM 或动态，元→万元）；PB = 归母普通股股东权益（元→万元）
- 亏损/负净值股**不剔除**：合成法天然扣减，剔除会系统性高估行业值
- 仅三类数据异常剔除（告警分原因）：无指标数据 / 无市值 / 自由流通占比越界（ratio > 1，Tushare 黑盒口径防御）
- 财务接口失败**整体降级**（该指标列"—"），涨幅榜不受影响——估值是单日榜"顺带"指标

## 3. 指标一：行业 PE（净利润四口径：归母/扣非 × TTM/动态）

### 3.1 数据与每股 TTM（TTM 口径）

- 数据：**归母净利润 = `profit_dedt + extra_item` 行内合成**（元，恒等式与实测覆盖率见第 2.1 节；
  接口无归母绝对额字段）——归母口径是"市价 ÷ 盈利"的通用定义（新闻/数据商行业 PE 均用归母）
- **业绩快报双源 PIT 合并（2026-08-27 新增，`_merge_attr_with_express`）**：报告期值若快报
  （`express_vip.n_income`，即归母净利润、未审计初步数）发布更早，则年报披露前以快报值参与——
  合并可用日 = min(财报日, 快报首版日)（"最新期"按此选取）；值优先级 = **审定优先**（fina 已可用
  且归母非空用 fina，否则快报 ann_date ≤ D 的最新修正版本；fina 可用但归母为 None 也回退快报）；
  TTM 三期各自独立解析；快报池失败退回纯财报口径（仅告警）。实测口径与量级：快报与审定值中位差
  ~0.7%、43% 差 >1%、~10% 差 >10%（减值/公允价值等审计时才定）；2025-04-07 快报参与 1060 只
  （年报未披露而快报已出，最新期从 Q3 提前到年报）；stats 加
  `stocks_express`（CLI 统计行打印"快报参与 N 只"）
- **扣非-TTM 口径（`get_ts_code_to_ttm_deducted_profit`）**：与归母同批数据、同规则一次全部算出
  （换字段不换算法），Web"净利润口径"下拉可切换显示（默认归母-TTM，CLI 的 PE 列固定归母-TTM）
- **累计值口径**（关键）：利润字段为年初至今累计值，禁止对多期累计值直接求和（会放大 2~3 倍）
- **标准式（主力路径）**：`TTM = 归母(最新期) + 归母(去年年报) − 归母(去年同季)`
  （不做单季差分：年报经审计、三季报未审计，公式只做一次加减，与数据商一致；最新期为年报时
  "去年同季"=去年年报，自动退化为年报值）
- **不足四期兜底（年化估算）**：去年年报或去年同季缺失时 `TTM = 归母(最新期) × 4/k`，
  k = 最新报告期覆盖的季度数（Q1→1、中报→2、三季报→3、年报→4）；
  系数按"报告期覆盖季度数"而非"历史期数"（年中起报的股票按 k 缩放更准）
- 最新期归母合成失败 → 按无财报处理（stocks_missing 统计），不回看更早期
- 无任何 `ann_date ≤ D` 报告或利润字段全 NaN 的股票 → 无 TTM，不参与

### 3.2 合成

```
每股股东值(万元) = TTM 归母(元) / 1e4
PE_free  = Σ free_mv / Σ (股东值 × ratio)      自由流通市值口径
PE_total = Σ total_mv / Σ 股东值                总市值口径
```

### 3.3 动态口径（`get_ts_code_to_dynamic_profit`，2026-08-28 新增）

- **定义**：`动态净利润 = 最新报告期累计利润 × 4/k`（k 同上：Q1→1、中报→2、三季报→3、年报→4）
  ——即把 TTM 的"不足四期兜底"年化式用于**全体股票**，与 Tushare `daily_basic` 动态市盈率、
  行情软件"动态 PE"同法；四口径中归母动态含快报双源合并（与归母 TTM 同一 `_attr_merged_view`
  视图）、扣非动态纯财报（扣非无快报源）；PIT 同 `_fina_latest_period`（最新期 ann_date ≤ D）
- **特性**：
  - 最新期为年报时 k=4，动态=年报值=TTM 退化式——**年报披露后至下期季报披露前，动态 PE ≡ TTM PE**
    （对四期齐备公司；可作两列的一致性自检）
  - Q1 披露后（约 5~8 月）动态 = Q1×4，**季节性强**的公司（旺季在 Q4/Q1，如白酒/白电）动态 PE
    显著偏低、动态同比显著偏高——动态口径固有特性（默认口径仍为归母-TTM，切换时自知）
  - 不足四期的新股其 TTM 本就走 ×4/k 兜底，动态与 TTM 天然同值
- stats：`{"periods", "stocks_dynamic"(参与), "stocks_missing"}` + 归母口径 `stocks_express`（与 TTM 共享计数）
- 数据与 TTM 同批（主窗口 [D-24月, D] 已拉），**零新增请求**；合成公式与 3.2 同构（仅换股东值）

## 4. 指标二：行业 PB（归母普通股股东权益）

### 4.1 数据与每股净资产（2026-08-27 改为权威绝对额）

- 数据：`balancesheet_vip` 的 **归母普通股股东权益绝对额**（`归母权益 − 其他权益工具` 行内合成，
  恒等式与对账证据见第 2.1 节；`get_ts_code_to_equity`）——**不经"每股×股本"折算**
- **净资产是报告期末时点值、不是累计值** → 无 TTM 滚动、无年化兜底：每股净资产 = `ann_date ≤ D`
  最新报告期的普通股东权益（PIT 规则与 PE 完全一致；新股仅一期也直接用其最新期）
- 单股 PB（总市值口径）= 当日总市值 / 归母普通股股东权益
- 无数据（`balancesheet_vip` 记录缺失 / 字段全 NaN）的股票 → 不参与
- **为什么改**：旧口径 `bps × 当日总股本` 把"报告期每股净资产"乘上"当日股本"，在两处股本口径
  不一致时出错（实测全市场 20250407 差异 >5% 的 231 只）：送转/增发/回购窗口（bps 分母为报告期
  股本、当日股本已变，如国泰君安/国联证券吸收合并增发、中钨高新发行股份购买资产——旧口径高估
  净资产最多 2 倍）、CDR（九号公司 `bps` 分母与 `daily_basic` 总股本差 10×，旧口径 PB 低估 10 倍）、
  次新 bps 分母漂移（302132 差 4.5×）；绝对额口径天然免疫。旧路径 `get_ts_code_to_bps`
  （bps×当日股本）保留作对照

### 4.2 合成

```
每股股东值(万元) = 归母普通股股东权益(元) / 1e4
PB_free  = Σ free_mv / Σ (股东值 × ratio)      自由流通市值口径
PB_total = Σ total_mv / Σ 股东值                总市值口径
```

- 行业净资产合计 ≤ 0 → 显示"资不抵债"（负净资产股不剔除，合成法天然扣减）

### 4.3 口径核对（已实测）

- 新旧口径对账（20250407 全市场）：567/998 个行业值与旧口径一致到 0.01%（普通股东权益与 bps 分子
  同口径的直接证据）；差异集中在上述股本错配个股（其他运输设备 +369% 即九号公司 CDR 修复、
  钨 +18~21% 即中钨高新增发修复、证券Ⅲ +7.9% 即吸收合并窗口修复）
- 旧 `单股 PB = close / bps` 曾与 Tushare `daily_basic.pb` 逐股对照一致（000001/600036/600519 差
  0.0000、601318 差 0.0001，见 `known_issues.md` 第 37 条①）；**不使用** `daily_basic.pb` 字段本身——
  它无法按 `ann_date` 做 PIT（历史日期会把以后才披露的净资产混进来），且行业合成需要净资产绝对额
  而非单股比值

## 5. 指标三：行业净利润同比（TTM 式与动态式，列名"净利润同比"）

### 5.1 TTM 式（默认，2026-08-27 新增）

- 个股：`增长 = TTM(D) / TTM(D-1年) − 1`，两期均走归母 TTM 机制（含业绩快报双源合并、PIT、
  4/k 兜底——与 PE 分子完全同源）；基期 = 同日历日去年（2/29 回退 2/28），报告期窗口自动落到
  [D-36 月, D-12 月]，预热在主日期之后串行补拉（共享报告期命中 period 缓存，实测仅多 4 期
  +8 次请求；2022~2023 旧报告期行数触顶 9999 自动翻页各 2 页）
- 行业：`Σ TTM(D) / Σ TTM(D-1年) − 1`（与 PE 的 Σ市值/Σ股东值 同构；亏损股不剔除、负值参与
  合计，扭亏/转亏个股的贡献自动进入 Σ）
- **双市值口径（2026-08-30 改，原无市值维度单列）**：total = 上式全值（=原实现，ratio≡1 的
  退化）；**float = Σ(当期×ratio) / Σ(基期×ratio) − 1，ratio = 当日 free_mv/total_mv 固定快照**
  （分子分母同权重，同比纯粹反映利润变化；与 PE(free) 的分摊公式同一结构——自由流通股东
  视角的盈利同比）；两口径**类别独立判定**（类别可不同：全公司数值型而自由流通盘"转亏"，
  实测农林牧渔 csi800 档 float=转亏 / total=-92.5%，源于盈利主力金龙鱼自由流通占比仅 10%
  而亏损养殖股占比 80%——盈利与自由流通结构错位的信号）；ratio 缺失/越界的股票仅从 float
  口径剔除（stats `pool_ratio_invalid`，不连坐 total）；**等权模式显示"—"**（与 PE/PB 一致，
  原显示全值）；CLI 固定打印 total 视角
- **参与 = 两期 TTM 均有的成分股（both-or-neither）**：缺基期的新股（上市不满约一年半）不进
  分子也不进分母（只进分子会系统性抬高增速），计入 stats `stocks_no_base`
- 基期为"当前快照回看"：含基期日之后发布的财务更正（与 PE 历史回看同口径，见 known_issues 第 39 条）

### 5.2 动态式（2026-08-28 新增，`get_ts_code_to_dynamic_growth_pair`）

- **定义（同相位累计同比）**：`增长 = 最新期累计利润 / 去年同季累计利润 − 1`，去年同季 = 最新期
  报告期整数平移 12 个月（20250331↔20240331），**对比相位严格对齐**；数学上等价于
  "动态值 / 去年同期动态值"（分子分母同期，4/k 年化系数约掉），与 Tushare
  `fina_indicator.netprofit_yoy`（累计同比）同口径
- **为什么不用 `动态(D) / 动态(D-1年)`（两时点各取最新期年化再作比）**：两时点的"最新报告期"
  由各公司披露节奏决定、可能错位——例：D=2025-04-15 时某股 2024 年报已披露（分子=年报实际值），
  而 D-1年=2024-04-15 时其 2023 年报尚未披露（分母被迫用 2023Q3×4/3 年化外推值），财报期错位
  一季 + 分母被年化放大，同比显著失真且每股异向、行业 Σ 混合放大；同相位定义无此问题。
  TTM 式的"两时点回看"之所以成立，是因 TTM 为完整滚动 12 个月、两期同构可比（TTM 机制会把
  当时最新期拼回完整年度），"动态"是年化外推、无此性质——不能照搬
- **去年同季取值**：优先从**主窗口 [D-24月, D] 的 D 视角**取审定值（去年同季的披露日可能晚于
  D-1年，从基期窗口取会被 PIT 过滤为 None）；最新期早于 D-12月 的长期停披股其去年同季 < D-24月
  不在主窗口，回落 TTM 同比的基期预热窗口兜底（该期在 D-1年 时点必然已披露，两段取值语义均完备）
  ——全部命中既有预热**零新增请求**
- 行业合成 / both-or-neither 参与 / 五级类别与排序 / "当前快照回看"口径：与 TTM 式完全一致
  （`classify_profit_growth` 同一判定，`Σ 当期 / Σ 去年同季 − 1`）
- **四口径（归母/扣非 × TTM/动态）一次全部算出**，共用已拉报告期数据零新增请求，Web 随
  "净利润口径"下拉切换（接口字段 `profit_growth_{basis}`）；扣非无快报源——年报季（1~4 月）
  扣非增长时效落后归母一档；**类别四口径独立判定**（归母扭亏而扣非仍亏损真实存在——
  非经常性收益保壳，实测 20250407 归母/扣非类别不一致 631 只）

### 5.3 TTM 式与动态式的数值差异（口径特性，非 bug）

两式衡量的窗口不同：动态式完全反映**最新一期报告期**的同比变化，TTM 式为**近 12 个月滚动**同比
（最新季的变化被其余三季稀释、更新慢但平滑）。例（D=2025-05-20，Q1 已披露）：某股 2025Q1 净利
3 亿、2024Q1 为 2 亿、其余三季两年合计均 7 亿——动态同比 = 3/2−1 = **+50%**，TTM 同比 =
(7+3)/(7+2)−1 ≈ **+11%**。季节性强或单季波动大的公司两式差距更大（这正是同时提供两式的意义）。

### 5.4 显示与排序（两式同一规则，个股与行业一致；2026-08-29 原"持续亏损"拆分为两档）

| 显示 | 条件（当期/基期） | 排序位 |
|---|---|---|
| 数值 ±xx.xx%（<100%）/ +x.xx倍（≥100%） | 两期均 >0，∈[−100%, ∞) | 中间，数值升序 |
| 扭亏 | 当期 >0、基期 ≤0 | 最高（高于一切数值） |
| 转亏 | 当期 ≤0、基期 >0 | 低于一切数值 |
| 减少亏损 | 两期均 ≤0 且当期持平原或收窄（当期 ≥ 基期） | 低于转亏 |
| 加大亏损 | 两期均 ≤0 且当期更深（当期 < 基期） | 最低 |
| — | 无数据（键缺失） | 恒置底 |

排序位从低到高：**加大亏损 < 减少亏损 < 转亏 < 数值 < 扭亏**。

- 数值**分档显示**：≥100% 用 `+x.xx倍`（值÷100，如 +955% → +9.55倍）、<100% 用带符号两位小数 %
  （负值恒 <100% 不涉倍档）；**仅数值着色**（红涨绿跌同涨幅列），
  类别文本（扭亏/转亏/加大亏损/减少亏损）与无数据不着色；扭亏类比值无定义（负基数），类别化恰好避免
  微利基数股以 +4000% 霸榜；数值不封顶（极端低基数真值照显，例见第 9 节）；**排序按真实数值**、
  不受显示分档影响；Web 主表/子表（`formatGrowth`）与 CLI 单日/区间（`_fmt_growth`）同一分档规则
- Web 排序经 `growthSortValue` 把类别映射为 ∓1e12 量级哨兵数值进入通用比较器
  （加大亏损 −3e12 / 减少亏损 −2e12 / 转亏 −1e12 / 扭亏 +1e12）

## 6. 指标四：行业 ROE（加权平均算法，四口径，2026-08-28 新增）

### 6.1 算法定位与数据锚（为什么不自建 9 号公式）

- 算法依据为证监会《公开发行证券的公司信息披露编报规则第 9 号——净资产收益率和每股收益的
  计算及披露》，**加权平均净资产收益率** = P ÷（E₀ + NP÷2 + Σ按月加权的事件项），其中事件项
  （发行新股/债转股新增、回购/现金分红减少、其他交易或事项引起的增减变动）各自按"发生次月起
  至报告期期末的月份数 ÷ 报告期月份数"加权
- **本模块不自建 9 号公式，以披露值为唯一权威锚**：`fina_indicator_vip` 同批带回的 **`roe_waa`**
  即公司按 9 号规则自行披露的加权平均 ROE（%，报告期年初至今累计口径），随现有批拉**零新增
  请求**。自建逐笔事件项在本项目数据源下**不可拼全**（2026-08-28 实测排查：增发无对应接口——
  `add_share`/`share_change`/`share` 均不存在，Tushare 股本类仅 `share_float` 限售解禁不改变
  净资产；`repurchase` 回购接口存在但金额与净资产入账口径不一致（库存股/注销差异）；其他综合
  收益等杂项变动无逐笔数据，财报只有季末累计值）——而披露值天然含全部事件项
- **官方加权分母反推**（E_waa，全部四口径的分母基石）：
  `E_waa(期) = 该期归母净利润(纯财报行内合成, 与披露 roe_waa 同口径) × 100 ÷ roe_waa(%)`
  分母即公司披露口径的加权平均净资产（含事件项）；归母与 roe_waa 同号时商恒正，
  **反推结果 ≤ 0 视为数据异常按无数据处理**

### 6.2 数据可得性实测（2026-08-28，全部真实调用）

| 排查项 | 结论 |
|---|---|
| `roe`/`roe_dt`/`roe_waa`/`roe_avg` 字段存在性 | 均随 `fina_indicator_vip` 真实返回（请求即带回、静默忽略坑不涉及）；`roe_waa`=加权披露值 |
| 加权口径验证（方向检验） | 茅台 2025 中报 roe_waa 17.89 **低于**摊薄 roe_dt 19.24（6 月巨额分红压低期末净资产→摊薄分母被压小）；招行相反 roe_waa 6.93 **高于**摊薄 5.95（期内利润累积使期末净资产高于平均）——两方向均符合口径定义 |
| 扣非加权 ROE | **无字段**（`roe_kf`/`deduct_roe` 等候选实测全部被静默忽略）→ 扣非两式自建（自建分子 ÷ 官方反推分母） |
| `roe_waa` 覆盖率 | 20250630 全市场 6488 只中 6374 只归母+roe_waa 齐备 = **98.2%**；招行同报告期两行（一行 roe_waa 全 NaN），字段级去重天然适配 |
| E_waa 反推对照 | 招行 2025 中报反推 E_waa 1.082 万亿 vs bs 池 (期初+期末)/2 = 1.064 万亿，**偏差 1.7%**，量级严丝合缝 |
| 简单平均 vs 官方加权分母偏差 | 全市场对照 |E_waa−(E₀+E₁)/2|/平均净资产：**中位 2.9%、P90 12.8%、约 1/3 公司 >5%**（分红/增发集中期更甚）——**自建简化式（去事件项）偏差不可忽略**，为"披露值缺失直接降级"的依据 |
| 同请求零新增请求 | `roe_waa` 加入 `fina_indicator_vip` 的 fields 列表即可，与 profit_dedt/extra_item/bps 同批带回，**单日全流程 API 计数不变** |

### 6.3 每股计算（`market_data.get_ts_code_to_roes`，四口径一次算出）

数据结构为**每股 (分子, 分母) 对**（与 TTM 增长对同构）：个股 ROE% = 分子/分母×100；
行业整体法 ROE% = Σ分子/Σ分母×100（第 6.4 节）。PIT 与 TTM 同规则（最新期 ann_date ≤ D）。

四口径（basis 与 PE/净利润同比的 `PROFIT_BASES` 联动，P=最新期、k=P 覆盖季度数）：

| 口径 | 分子 | 分母 | 公式要点 |
|---|---|---|---|
| `attr_dynamic` | 归母累计(P) × 4/k | E_waa(P) | 等价于 `roe_waa(P) × 4/k`（分子分母同乘系数，披露值直接年化——动态 ROE 的定义即此） |
| `deduct_dynamic` | 扣非累计(P) × 4/k | E_waa(P) | 扣非无披露值，自建分子 ÷ 官方分母 |
| `attr_ttm` | **纯财报归母 TTM**（不经 express 合并） | E_TTM | 分子与披露分母同源同期（快报归母不参与，见 6.5） |
| `deduct_ttm` | 扣非 TTM | E_TTM | 分母与 attr_ttm 共用 |

**TTM 分母 E_TTM 的分段推导**（复用 TTM 标准式同一组报告期 P=最新期 / A=去年年报 / S=去年同季）：

```
E_TTM = E_waa(A) + (E_waa(P) − E_waa(S)) ÷ 2
```

推导：TTM 区间 [去年同期末, 最新期末] = 去年下半年 + 今年年初至今。全年披露 E_waa(A) 时间
加权覆盖 12 个月、上半年披露 E_waa(S) 覆盖前 6 个月，展开得 E_下半年 = 2×E_waa(A) − E_waa(S)，
与 E_waa(P)（=今年年初至今）按 6/6 等权合并即得上式。**最新期为年报时 S=A**，自动退化为
上下半年平均 (E_waa(P)+E_waa(A))/2。三段全部使用披露值反推的官方加权分母，精度与单期披露
一致（优于任何自建平均式）。A 或 S 的 roe_waa 缺失（如新股、披露不全）或推导结果 ≤ 0 时
**兜底 E_TTM = E_waa(P)**——与 TTM 分子 4/k 年化兜底天然配套（分子分母同一报告期）。

### 6.4 行业合成与显示（`industry_ranking.daily_roe`）

- 行业值 = **按当日市值权重的个股 ROE 加权算术平均** Σ(市值ᵢ×ROEᵢ)÷Σ市值ᵢ×100（指数按什么
  权重分配成分股、指标就用什么权重）：**双市值口径**（自由流通/总市值）随加权方式切换、
  等权模式无市值权重与 PE/PB 一致显示"—"；个股 ROE 为负（亏损）正常参与加权（算术平均对
  负值稳定）；**各口径覆盖互不连坐**（扣非缺失仅缺扣非两档）
- 接口字段：主表 `roe_waa_{basis}_float`/`roe_waa_{basis}_total`（字段名带算法段 `roe_waa_`，
  将来新增算法如摊薄 `roe_dt_` 不破坏现有键），子表（个股纯比值、无市值段）`roe_waa_{basis}`；
  Web"ROE算法"下拉当前仅"加权平均ROE"一档，ROE 分子另随"净利润口径"四档下拉联动；
  CLI 打印默认口径（归母-TTM）两列（自由流通/总市值）
- 显示：正数两位小数 + %（**不带 + 号、不着色**）、负值显示**"亏损"**、无数据（键缺失）显示"—"
  恒置底；排序为纯数值序（"亏损"显示不参与排序——仍按真实负值排，亏损行业自然置底）

### 6.5 边界与降级

- **全链不接业绩快报**：`express_vip` 无 roe_waa，分子若用快报利润会与披露分母期次错配
  （宁缺勿错配）——快报窗口内（年报季 1~4 月）ROE 时效停在上一报告期，落后 PE/净利润同比
  一档；注意同档"归母-TTM"下 PE 分子含快报而 ROE 分子不含，两列时效可能差一档，属预期
- **roe_waa 缺失或反推异常 → 该股四口径全部无数据**（显示"—"），**不做自建简化式兜底**：
  简化式（(E₀+E₁)/2 或 E₀+NP/2）与官方加权分母偏差实测中位 2.9%、1/3 公司 >5%，披露值缺失时
  宁缺勿猜；20250630 实测缺失约 1.8%
- 扣非累计缺失的股票仅扣非两档无数据（归母两档不受影响）
- stats（CLI 统计行）：`periods` / `stocks_with_roe`（最新期 roe_waa+归母齐备）/ `stocks_missing` /
  `stocks_ttm_full`（E_TTM 三期齐全）/ `stocks_ttm_fallback`（E_TTM 兜底）/ `pool_no_value`
- 财务接口失败整体降级（该列全"—"），涨幅榜不受影响——与其他指标一致

## 7. 指标五：行业股息率（Web 列名"回报率"，总额法 DPS 双口径 + 注销合并口径 est_bb，2026-08-28 新增、est_bb 2026-08-30 新增）

### 7.1 为什么不用 Tushare 现成股息率字段（口径黑箱破译，2026-08-28 逐日实测）

`daily_basic` 自带 `dv_ratio`（股息率）与 `dv_ttm`（股息率TTM），实测加字段即得，但逐日数据
破译出二者的真实算法后判定**不能作主列**——它们恰是"滚动窗口混合财年"的两类失真口径：

| 字段 | 实测破译的口径 | 证据 |
|---|---|---|
| `dv_ttm` | **纯"除息日滚动12个月"**：过去12个月除息事件分红加总 ÷ 当前市值 | 长电逐日跳变逐日吻合除息事件进出（2025-01-24 中期除息日分子 0.82→1.03、2025-07-18 年度除息日 1.03→0.943） |
| `dv_ratio` | **"上一自然年度除息"**：除息日落在上一自然年的分红加总 ÷ 当前市值，每年首个交易日切换 | 长电 2024-01-02、2026-01-05（两年首个交易日）分子精确切换 |

二者在场景中的失真实测：**场景1（一次转多次）**——神华 FY2025 首改中期+年度（0.98+1.03），
2025-11-10 中期除息后 `dv_ttm` 分子=上财年年度 2.26+本财年中期 0.98=3.24，从 5.49% 跳至
**7.88%，连续 8 个月高估 43~61%**；**场景2（多次不均衡）**——节奏稳定时全年正确（长电 0.21+0.733
稳定 0.943），失真仅在节奏改变的过渡期。附带缺陷：分子为**总额稀释口径**（每股×当时股本÷
当前总股本，长电可转债转股 +3.9% 使 0.8533 稀释成 0.8212 分毫不差）且股本变动日分子跳变。
官方字段仅保留作对照。

### 7.2 自建口径：财年锚定 + 总额法（对两类场景免疫）

- **财年归属**：每个分红事件（`dividend` 接口）按 `end_date`（分红年度）年份前缀归属财年——
  `1231`=年度、`0630`=中期、`0930`=三季度（茅台型中期挂三季报）、`0331`=一季度、
  **非报告期日期=特别分红**（茅台 `20221129`/`20231121` 型，计入财年总额、不触发锚切换）；
  同财年多事件直接加总——场景1/2 天然免疫（新旧年度分红各归各的财年，永不混合）
- **总额法**：每股口径 = Σ(每股派现 × 该事件基准股本 `base_share`) ÷ 当前总股本——与官方
  dv_ratio 稀释口径一致，正确处理财年内送转（10送10 后每股基数不可直接相加）；
  `base_share` 缺失的事件按"基准股本=当前总股本"退化；**当前总股本缺失**（整个上市期无
  daily_basic，极罕见）时退化为每股金额直接相加（忽略 `base_share`——"每股×万股"与每股
  口径混合无意义）且 payout 估算无定义跳过、由实绩兜底，主表合成侧该股本就因无股本剔除
- **事件级级联：实施 > 预案 > 无**。只认实施与预案两态（`div_proc` 实际 5 态：预案/股东大会
  通过/实施/停止实施/预披露，文档只写 2 种）；实施行按 (ex_date, 金额) 去重（茅台 FY2024 双
  实施行实测）、预案取最新公告日（同日双预案=股本调整行）；**停止实施行作废公告日更早的
  预案**（长电 2024 中期先停后重报实测）；**绝不使用"股东大会通过"行**——其 ann_date 被回填
  为预案日且携带股东大会才通过的修订金额（中移动 FY2022 预案 2.21/决案 1.9796 同盖
  20230324），按它重放历史会用未来信息（PIT 脏）
- **预案修订风险（接受并实测有界）**：预案→实施金额修订率 **3.2%**（中位 0.44%、p90 1.57%、
  >10% 尾部 2/1027——大秦铁路 −13.2%、中移动 −10.4%），仅存在于"预案后约 2 个月"窗口、
  实施落地自愈；"有预案但从未实施且无停止实施行"的幽灵取消实测 **0**；预案先行把每股锚切换
  从 6 月中提前到 3~4 月（中位早 56 天），中期/三季度分红也提前 41 天计入

### 7.3 锚定与完整性（三态判定）

- **静态锚 = 最近完整分红年度**：年度事件（end_date=*1231）**有实施或有预案**的最近财年
  （自当前财年降序走查，首个齐备财年即锚；分批除息实测为零，触发时点唯一）
- **完整性三态**：
  1. **有行即齐备**：年度事件存在实施/预案任意行——**含 0 金额预案行 = 显式"不分配"**
     （实测 219 例全部 4 月年报季公告），多数不分红公司 4 月即确立为零
  2. **无行且过 7/31（Y+1）→ 推定年度分红为零**：年报法定披露截止 4/30 + 缓冲；实测
     FY2021~24 共 867 个年度预案行晚于 5/31 的为 0（最晚 5/11），而"无预案行"的已实施事件
     占 7.3%（北交所/深B 覆盖缺口集中板块），其实施公告晚于 7/31 的仅约 **0.3% 支付者**
     （8/1~8/22 落地，误判 ≤3 周自愈）——7/31 为时效与误判的定稿平衡点（8/31 误判归零但
     沉默不分红者确立零晚一个月）
  3. **其余未知**：锚留上一完整财年，不提前归零；新股无完整财年 → 无锚
- **停发现象量级**（为何三态必要）：每年 8%~19% 的历史分红公司当年年度归零（250 只样本逐年
  实测），0 金额预案行 + 7/31 推定分别覆盖"显式不分配"与"沉默不分红"

### 7.4 双口径定义（列名"回报率"，Web"回报率口径"下拉）

- **静态股息率**：锚财年分红总额（级联值，4~6 月窗口含在途预案）÷ 当前总股本——上一个完整财年的
  事实，阶梯式更新（与 PE-LYR 同构；股息粘性下滞后通常 <15%，长电成长期极端 −13%）
- **TTM估算股息率（Web 默认）= 进行中财年 N 的估算，宣告优先、外推补位，随每期利润报告刷新**：
  - **估算目标** = 年度分红尚未宣告的最近财年 N；**每个报告期披露（Q1/中报/三季报/年报 ± 快报，
    与 PE 同源同 PIT）都重算一次**——N 年报分红宣告（预案，3~4 月 N+1）瞬间目标滚到 N+1、
    payout 锚切到 N，**估算全年 12 个月无空档**（一季报与年报发布很近，滚动无缝）
  - **估算值 = payout(锚) × 归母TTM ÷ 当前总股本**，payout(锚) = 锚财年分红总额 ÷ 锚财年归母
    净利润（年报值，与分红预案同日披露）；**payout 封顶 95%**——锚年利润塌方/分红刚性/特别分红
    会造出 payout>100% 的异常锚（实测五粮液 FY2025：分红 200 亿 ÷ 归母 89.5 亿 = 223.5%，未封顶
    估算 10.20% 比公司实付 5.16 元还高 41%；封顶后估算 4.34%，回到"利润的 95% 折算"的保守上界，
    静态对照 7.25%）；**TTM ≤ 0 按 0 利润估算**——某季度大亏把 TTM 拖负时估算 DPS = 0，
    个股按 0.00% 参与行业合成而非"—"（"分红率稳定"假设下亏损期分红为零的正确推论，
    2026-08-28 定稿；TTM 缺失[无财报新股]仍无定义；**锚年亏损但仍在分红（profit ≤ 0 且总额 > 0）按 payout=0 估算 → 0.00% 参与合成**——2026-08-30 定稿，实测城建发展/华发股份 FY2025 亏损仍派现触发，实绩接管自动生效；**宣告替换外推而非取大**——公司预案是权威宣言，
    利润暴涨使外推更高时也以公司预案为准
  - **部分实绩防低估**：N 的中期实绩/宣告（级联部分值）**超过估算时用实绩**，否则维持估算
    （原"已实施超过才替换"规则）
  - **实测精度**（过渡期观察点）：神华 2025-12-01（首改中期+年度）估算 −5.5% vs 纯TTM +61.2%/
    静态 +12.4%；长电 2025-04-30 估算 −15.2%（利润 TTM 滞后传导——乌白注入利润下半年爬坡、
    年报才补进 TTM；分红率本身稳定 70.9%→71.1%）——两类误差源（利润 TTM 滞后、分红率政策
    变化、特别分红抬高基数）写进已知边界
  - **停发锚**：锚财年总额=0 → 估算恒 0.00%，不猜复分红（复分红由预案级联接管，4 月预案一出
    即替换，外推 0 最多存活 1~3 月窗口）
  - **滚动跳变**：目标财年滚动的瞬间列值从 estimate(N) 跳到 estimate(N+1)——健康情形连续
    （estimate(N)≈宣告(N)≈estimate(N+1) 起点），利润/分红率突变时跳，属"列=进行中财年估算"
    的语义本身
- 个股股息率% = DPS ÷ 收盘价 × 100（子表，无市值段字段 `div_{basis}`）；行业值 = **按当日市值
  权重的加权平均** Σ(市值ᵢ×股息率ᵢ)÷Σ市值ᵢ（指数按什么权重分配成分股、指标就用什么权重）：
  **total 口径** = Σ(DPS×总股本)÷Σ总市值（数学上恒等于个股总市值股息率的市值加权平均，即原
  整体法）、**float 口径** = Σ(DPS×自由流通股本)÷Σ自由流通市值（自由流通盘的现金回报，系统性
  高于 total；自由流通股本=自由流通市值÷收盘价，停牌无收盘价仅缺 float 口径）；双口径字段
  `div_{basis}_float`/`div_{basis}_total` 随加权方式切换，等权模式与 PE/PB 一致显示"—"
- 显示：两位小数 + %（不带 + 号、不着色）；**0.00% = 齐备零分红（事实数值，参与合成与排序）**，
  键缺失 = 无数据（"—" 恒置底）——0 与未知严格区分；接口字段 `div_est`/`div_static`

### 7.5 边界与降级

- **官方字段对照**：自算静态/估算与官方 `dv_ratio`/`dv_ttm` 的差异属口径设计（财年锚定 vs 滚动
  窗口），非数据错误；对照方法见 7.1
- **估算利润源继承 PE 边界**：含快报（年报季时效快一档）、TTM 不足四期 4/k 年化、历史回看含
  更正（known_issues 第 39/40 条同款）
- **分红缓存**：`dividend` 接口按 ts_code 全历史拉取落盘（`data/dividend_history.json`），首刷
  约 5400 请求 ~12 分钟（一次性）；增量 = ann_date（**日历日**，公告可有周六如神华 20250830）+
  ex_date（交易日）双通道逐日探测、受影响股票整股重拉，并**顺带补拉缓存未覆盖的新成分**（新上市
  股票首份分红公告前不在任何探测通道内）；**`--full` = 忽略现有缓存全量重拉**（只补缺失会把
  last_refresh 推到今天而跳过增量窗口、旧股票新事件漏拉）；探测与单股拉取均 offset/limit 分页
  循环（实测单日峰值约 3000 行单页即回，分页为极端披露日防御）——双通道必要性：部分实施行
  ann_date 被回填为预案日仅扫公告日会漏
- stats（CLI 统计行）：`stocks_total` / `stocks_static`（静态有值）/ `stocks_static_zero` /
  `stocks_static_fallback`（7/31 推定）/ `stocks_est` / `stocks_est_zero` / `stocks_est_realized`
  （实绩接管）/ `stocks_est_payout_capped`（payout 封顶）/ `stocks_est_zero_profit`
  （TTM≤0 按 0 利润估算）/ `stocks_est_zero_payout`（锚年亏损按 payout=0 估算）/ `stocks_no_anchor` / `stocks_no_profit`（利润缺失/未披露）/ `stocks_no_share`
  （当前股本缺失，DPS 按每股退化）/ `pool_no_value` / `pool_no_mv`
- 分红缓存刷新或财务接口失败整体降级（该列全"—"），涨幅榜不受影响

### 7.6 合并口径 est_bb："TTM估算股息+注销率"（台阶法注销分量，2026-08-30 新增）

- **定位**：在"TTM估算股息率"分子上加**回购注销分量**——分红看承诺（当财年宣告/估算）、注销看
  行动（实际缩股），合并 = 以 TTM 利润为基准的年化股东回报。行业合成 = **分子金额相加再除同一
  分母**（不是两个比率相加）：`[Σ(DPS×股本) + Σ(注销金额)] ÷ Σ市值`，注销金额折每股
  （万元÷万股 = 元/股）后与 DPS 同量纲、聚合公式零特例；float 口径同构（注销金额×自由流通占比）
- **注销统计窗口 = 该股归母 TTM 净利润的覆盖时段**（`get_ts_code_to_ttm_window`，与"TTM估算
  股息率"的利润源完全同期同源、PIT 含业绩快报提前）：标准式 = **(去年同季期末, 最新报告期期末]**，
  逐股锚定、左开右闭、长度恒 12 个月；**窗口随报告期披露整体右移**——期内新注销最迟约 4 个月
  后随窗口右移计入（与 TTM 利润"披露后才进"同一逻辑，指标与 PE 同呼吸、季度间冻结）；次新股
  （4/k 年化兜底）左端不限（= 上市以来，注销金额≈0 可忽略）
- **台阶法**（Tushare 无回购注销专用接口，`repurchase` 只覆盖回购买入且不分注销/库存股，股本
  登记数据是注销的唯一权威事实源）：**总股本逐日 diff 只取负台阶**（正台阶=送转/增发/转债转股/
  激励行权，只识别不归因、不干扰负台阶——实测美的 2024~2026 首尾净变化 +5.9 亿股完全掩盖
  -1.77 亿注销，逐台阶是唯一正确姿势）；**回购进库存股不减股本 → 本口径天然只算已注销**（真
  回报股东），回购未注销的库存不计入；金额 = Σ(负台阶量 × 台阶日收盘)——价格口径实测误差：
  台阶日收盘茅台 -6.9% / 回购期 VWAP +2.8%（全市场批量取台阶日收盘零额外请求）
- **三层决策（价格证据 > 对冲启发式 > 数量级守卫， 2026-08-30 定稿）**：①**repurchase
  交叉验证优先**——完成公告 vol 与台阶量精确匹配（±2%）时**隐含均价 = amount/vol 即真实
  回购价格**：均价 ≈0（0/1 元注销， 对赌/激励类公司没花钱）→ 剔除（实测剔 165 笔： 天山
  生物/创新新材/润泽科技 42 亿/宝鼎/建发/中铁/中软等国企激励股 0 元注销）；均价正常
  （台阶日收盘 ×[0.1, 3] 带）→ **金额直接用公告 amount 并豁免下两层**（真实成本比市价准：
  茅台两批 60+30 亿精确值 vs 市价口径 85.9 亿；实测 697 笔[67%]用公告金额；救回被守卫误杀
  的科捷 7.1%/西山 6.3% 大比例真回购、被对冲误伤的蓝丰生化[真注销后 80 天相近量增发差
  1.59%]）；带外价格=amount 可疑视同无匹配；②**对称对冲（仅无价格证据）**：-X 后 90 自然日
  内 +X（≤2%）成对剔除（美的/百济两笔 546 亿/九号实测）；③**数量级守卫（仅对冲幸存）**：
  单笔占比 >6% 剔除（脏跳变兜底， 定稿后实测零命中）；回购公告缓存（按月全市场）未就绪时
  跳过交叉验证不降级；分批注销/月度累计 vol 不匹配 → 市价+守卫路径，详见 known_issues
  第 44 条③；小负台阶（激励股折扣价回购注销，市价高估约 3 倍）统一按市价
  估算、金额占比实测 ~3%，不单独修正
- **台阶日收盘定价的两类失真**：① 回购与注销几乎同期的主流场景误差 ±3~7%（茅台/美的实测）；
  ② **低价回购库存多年后转注销场景严重高估**——实测九号 2025-09-17 注销 600 万份 CDR
  （2024 年低价回购的激励库存变更为注销），年报回购成本 1.57 亿 vs 台阶日收盘计 4.22 亿
  （高估 2.7 倍，期间股价大涨）；2025 年注销式回购潮中此场景不少见，est_bb 的注销分量对
  此类股票是上界口径
- **数据与缓存**：`daily_basic` 按 trade_date 全市场单请求（与市值拉取同模式）逐日快照，与前日
  快照 diff **只落盘变化行**——持久缓存 `data/share_change_events.json`（{快照日+快照+事件
  {ts_code: [{d,p,n,x}]}}, 18.5 个月事件数万条、文件数 MB, 随仓库提交）；首刷回填 560 自然日
  全部交易日（约 370 请求、3 次/秒档约 2 分钟一次性），日常增量 = (快照日, 今天] 逐交易日链式
  diff；单日榜编排在最开始启动台阶外预热线程（与分红外预热并列）；手动补数/体检
  `python -m shenwan_industry.share_change_cache`（`--full` / `--check 个股`）
- **est_bb 产出规则**：仅对 est 有值的股票产出（est 缺失 = unknown ≠ zero，与股息率三态哲学
  一致）；窗口内无注销（金额 0）是数值（est_bb = 股息率本身）；**台阶缓存未就绪（未首刷）/
  刷新失败 → est_bb 整口径降级不产出**（前端该口径显示"—"），est/static 不连坐；无 TTM 窗口
  （无财报）的股票注销无法计入（bb_no_window 统计）
- **历史回看边界**：事件保留 560 自然日（≈18.5 个月）——查询日 D ≥ 今天−约 2.4 个月时窗口
  完整；更早的 D 其 TTM 窗口左端可能早于事件覆盖起点，注销分量被**低估**（计算时告警 +
  `bb_coverage_limited=1`，尽力而为继续）；股本快照的 A+H 公司 `total_share` 为全口径（H 股
  注销也是真回报、H 股增发是正台阶不干扰，语义正确）
- stats（CLI 统计行"回报率(注销分量/est_bb)统计"）：`bb_window_stocks`（有 TTM 窗口）/
  `bb_stocks`（窗口内注销 >0 只数）/ `bb_events`（计入负台阶笔数，对冲后）/
  `bb_amount_wan_total`（全市场窗口内注销合计万元）/ `bb_no_window`（有事件无财报）/
  `bb_coverage_limited`（历史回看覆盖受限）/ `bb_large_skipped`（守卫剔除笔数， 仅无价格证据）/
  `bb_vam_skipped`（0/1 元注销剔除笔数）/ `bb_amount_from_buyback`（用公告金额笔数）/
  `bb_vam_ready`（回购公告缓存就绪 0/1）；
  **键缺失 = 台阶缓存未就绪，est_bb 本次降级**
- 实测锚点（2026-08-30）：茅台 20260528 台阶 218.8614 万股与 `repurchase` 完成公告累计
  2,188,614 股分毫不差（×1275.98 = 27.93 亿）；美的窗口合计 74.9 亿（20251223 的 9,329.54
  万股×79.65 为主，20250626 的 -1,109 万股被正确排除在 (20250630, 20260630] 外、±109.6253
  对称对被对冲剔除）；20260828 全市场 TTM 窗口注销合计 1,944.8 亿 / 955 只 / 1,212 笔；
  白酒Ⅲ est 3.92% → est_bb 4.28%、空调 est 5.48% → est_bb 6.39%（total 口径）

## 8. 防御与展示约定

- 覆盖率：参与股票数与当日成分股数可对照（CLI 汇总统计、Web 表格值大小自行对照）；剔除告警按原因分类
- **成分股子表**（Web 单日榜与区间链式榜）：每只成分股也带 PE/PB/ROE/股息率/净利润同比列——PE/PB 为个股**总市值口径**
  （与行业总市值口径公式一致：PE = 总市值/所选口径净利润，PB = 总市值/归母普通股股东权益），ROE 为纯基本面
  比值（与行业同式），股息率 = DPS/收盘价（总额法 DPS ÷ 当日收盘价，与行业整体法自洽），净利润同比与行业同式，
  财务缓存命中零请求（`web/service._compute_stock_metrics` 单日与区间共用，区间以末交易日为时点、与主表指标
  同一点位）；亏损/资不抵债/缺失的显示与行业列一致（"亏损"/"资不抵债"/"—"）；区间口径已在外层主表
  （"共 N 个行业"后）注明、子表不重复；静态版区间榜子表不带这些列（显示"—"）
- 统计输出（CLI 每指标统计行 / 日志，PE/净利润同比/ROE 仅默认口径归母-TTM、回报率仅默认口径 TTM估算股息率）：
  - PE：报告期数、标准式 / 不足四期年化 / 无财报股票数
  - PB：报告期数、有净资产 / 无净资产股票数
  - ROE（加权平均）：报告期数、有披露值 / 无数据 / TTM 分母三期齐全 / TTM 分母兜底 / 池内无数据股票数（见 6.5）
  - 股息率：缓存覆盖 / 静态有值（零分红 / 7/31 推定）/ 估算有值（零分红 / 实绩接管）/ 无锚 / 无锚年利润 /
    池内无数据 / 无市值股本（见 7.5）；注销分量独立统计行：TTM 窗口有注销只数 / 计入笔数 / 合计金额 /
    有窗口股票 / 有事件无财报（见 7.6）

## 9. 性能与缓存

- 每计算日：`fina_indicator_vip` 12 期（当期 8 + 增长基期新增 4，**旧报告期触顶 9999 各翻 2 页**；
  ROE 的 `roe_waa` 随同批带回零新增请求，见第 6.2 节）+
  `balancesheet_vip` 8 期 + `express_vip` 12 期 ≈ **36 次请求**（实测 fina 16 / bs 8 / express 12）；
  **动态口径（动态净利润与动态同比的"去年同季"）全部命中这两个既有窗口、零新增请求**；三池各自
  二次调用命中缓存零新增请求，其余市值/行情全部命中现有缓存
- **并发优化**：每池 8 期请求经 `ThreadPoolExecutor(8)` 并发，开始时刻由**各自节流器**按 7.5/s
  错开、网络往返并行重叠（同区间行情三池预取的模式）；**各池之间也并行**（接口限额独立）
  ——实测多池并行总墙时 **~1.4~1.5 秒**（与单池同量级、不串行叠加；串行 ~3.5 秒；
  限速下限即 8×0.133s≈1.07s）；各聚合 ~0.03 秒
- **与全部计算阶段并行（后台预热）**：单日榜编排在**最开始**即启动后台线程
  （`prefetch_fina_indicators`：fina/bs/express 三池并行拉取），与六条涨幅序列计算并行
  （接口限流独立、只写各自财务缓存、与市值缓存互不相交）；PE/PB 阶段 join 该线程命中预热
  缓存——拉取的墙体时间被隐藏；任一池失败仅该池对应指标降级（bs 池失败只影响 PB）
- 浏览器/进程内二次计算同一天 → 报告期缓存命中，该阶段 0 请求
- 报告期数据按 period 内存缓存；每股各期合并按计算日缓存（`_fina_per_stock`/`_bs_per_stock`）；
  TTM / bps / equity 结果各自按计算日缓存；**第二期(2026-08-31)起三池原始行写穿 SQLite
  `data/market.db`（`fina_raw`/`bs_raw`/`express_raw`，报告期键、去重/PIT 留读取方零口径折叠）——
  距今 ≥24 个月的期跨进程读取零网络（历史复盘/同比基期长尾受益），更近的期每次走网络
  抓财报更正（与原行为一致），远期追溯修正走 `market_cache.py --force-fina`**
- 限流：`fina_indicator_vip` 与 `balancesheet_vip` 与 `express_vip` 各用独立节流器（7.5 次/秒 ≈ 450 次/分钟，互不影响）
- **注销分量（7.6 节）**：`daily_basic` 按日全市场快照 diff 落盘持久缓存
  （`data/share_change_events.json`，随仓库提交），首刷回填 560 自然日约 370 请求 ~2 分钟
  （一次性）、日常增量 = (快照日, 今天] 逐交易日 1 请求/日；TTM 窗口复用 fina 报告期序列
  **零新增请求**、金额计算纯内存毫秒级；单日榜编排与分红外预热并列启动台阶外预热线程
- **股息率（第 7 节）**：`dividend` 按股全历史拉取落盘持久缓存（`data/dividend_history.json`，随仓库提交），
  首刷约 5400 请求 ~12 分钟一次性、日常增量仅 (last_refresh, today] 窗口的 ann_date+ex_date 双通道
  探测（约 2×天数 次 + 受影响股票重拉）；单日榜编排与财务三池同时启动分红外预热线程（dividend
  接口限流独立），计算阶段 join 命中；DPS/锚/完整性全部本地计算零接口请求；每股 2000 积分即可
  调用（远低于池内其他接口门槛）

## 10. 已知边界

1. **PE 年化估算近似**：不足四期的新股按 4/k 外推，忽略季节性；年化占比高的行业（次新集中）
   PE 可比性下降，以 CLI 统计行判断，仅影响个别行业的小权重成分。**动态口径把该年化式用于全体
   股票**（第 3.3 节）——Q1 披露后季节性行业动态 PE 系统性偏低，属口径固有特性而非数据错误；
   年报期（最新期=年报）动态 ≡ TTM 退化式，两列数值相同
2. **PB 股本近似已消除（2026-08-27 改权威绝对额）**：旧口径"报告期 bps × 当日总股本"在送转/
   增发/回购/CDR/次新场景引入比例级偏差（清单见第 4.1 节），已改为 `balancesheet_vip` 归母普通股
   股东权益绝对额；残余近似仅为"报告期后到当日的利润累积/分红未反映"——这是所有财报频率 PB 的
   固有 staleness（数据商同样存在）
3. **自由流通占比黑盒**：`ratio` 依赖 Tushare `free_share` 口径（无扣减明细，见 `known_issues.md` 第 18 条），
   与官方《编制说明》附录二无法逐条核对；`ratio > 1` 极端值按越界剔除
4. **历史日期市值与财报口径**：估值分母用当日市值、分子用截至当日已披露最新财报（时间错配为行业估值
   的固有属性）；年报/中报披露季会随大批公司窗口切换出现跳变，属正常
5. **停牌股参与**：停牌股以回退市值参与（与涨幅权重一致），若整段上市期均无市值数据则不参与
6. **balancesheet_vip 覆盖差**：北交所（430xxx）与部分次新缺行（20241231 期较 fina 少 259 只），
   均不在申万股票池内、池内剔除数实测零变化；两接口"最新期"偶有不同步（20250407 实测 9 只，
   PIT 回退到不同期）；偶见畸形代码（`833243!1.BJ`）不匹配任何股票池，无害
7. **业绩快报为未审计初步数**：精度损失、覆盖范围与"扣非无快报源"的时效不对称均见第 3.1 节 /
   第 2.1 节；快报窗口内（年报季 1~4 月）单股 PE 会随快报修正/年报审计结果跳变——属 PIT 本义
   （当时市场看到的也是快报数）
8. **净利润同比边界**：TTM 式基期为"当前快照回看"（含此后更正，与 PE 历史回看一致）；本期标准式与
   基期 4/k 年化混用的股票同比略失真（动态式天然无此不对称——分子分母同为累计值同相位）；低基数
   行业出现极端百分比（实测社会服务 +955%、航海装备 +1151%，2024 vs 2023 真实低基数）不封顶照显；
   动态式的"去年同季"对停披超一年的股票取自基期窗口（D-1年 时点已披露值，见第 5.2 节），极长期
   停披（>2 年）无去年同季 → 不参与（stocks_no_base）
9. **注销分量（est_bb）边界（2026-08-30 新增，详条见 known_issues 第 44 条）**：台阶日收盘定价
   单股误差 ±3~7%（VWAP 更准但需历史行情，全市场批量不引入）；激励股折扣价回购注销按市价高估
   约 3 倍、金额占比 ~3%；事件保留 18.5 个月——回看 2.4 个月以前的日期注销分量低估（告警）；
   超长停披股（标准式窗口早于覆盖起点）同款低估；快报不改窗口端点（只改利润值， 端点纯由财报
   序列决定）

## 11. 行业指数估值走势序列（K 线副图 PE/PB，2026-08-31 新增）

单日榜 PE/PB 的**历史序列化**：对单只行业指数把第 3/4 节的同一公式逐交易日回放，供 Web K 线弹窗
副图指标查看走势（`valuation_series.py`，下拉"成交额/成交量/PE/PB"，仅行业指数可选）。**任取一日
序列值必须与该日单日榜对应列分毫不差**（同一 `daily_valuation_metric` 实现，实测锚点 20260828：
L1 农林牧渔 / L3 种子的 PE(free) 与 PB(free) 均一致，跨进程 ulp 级浮点差异见 known_issues 第 46 条②）。

- **口径（固定一种，不随主表下拉联动）**：PE = **自由流通口径 + 归母TTM**（`pe_attr_ttm` 的 free，
  即 `Σ free_mv ÷ Σ(归母TTM × ratio)`），PB = **自由流通口径**（`pb` 的 free）；样本 = 全池（全A，
  不随"样本空间"三档切换）；不提供总市值/等权/其他利润口径的走势（多口径图例爆炸，定稿只此一种）
- **窗口**：滚动 `VALUATION_WINDOW_DAYS = 365` 自然日（**2026-08-31 定稿 1 年**，原开发期 92 天/3 个月；
  延长只改常量、缓存按缺失日期增量补算），右端 = **今日之前最近交易日**（不含今日——当日行情盘后才完整，
  避免半日数据被缓存固化；隔日自动延长）
- **语义**：序列值 `null` = 已计算且行业亏损（PE）/资不抵债（PB），走势图**断线**展示；**键缺失 =
  未计算**（二者严格区分，与单日榜 None/键缺失一致）；K 线日期超出窗口左端/未计算的显示"—"
- **数据与成本**：逐交易日复用单日榜全部机制（PIT 财报窗口、`index_member_all` 历史归属、当日
  daily/daily_basic 全市场批拉）；每交易日 2 请求（daily + daily_basic 各一）+ 财报池约 36 请求
  （跨日期共享 period 缓存），1 年窗口首查 ≈ 520 请求（两接口并行各 ~245）、预计 6~8 分钟
  （92 天窗口实测 2~3 分钟按比例外推）；**第二只指数因共享
  `MarketDataProvider` 内存缓存（行情/市值/财报全部命中）仅纯 CPU 聚合、实测秒级完成**；
  **2026-08-31 起 daily/daily_basic 走 SQLite 持久层 `data/market.db` 三级查找（写穿入库，见
  `market_store.py`）——已入库的历史日期零网络（冷启动仅财报池重拉 + 未入库日期），跨进程重启同样命中**；
  **同日第二轮实测（行情已入库 + 逐日循环性能优化后，2026-08-31）：92 天窗口干净耗时 34.0s
  （cProfile 42.1s，构成：财报视图逐日重建 ~49% + 财报网络 ~37% + 过滤/归属/循环 ~12%），
  365 天外推约 2 分钟——上方"6~8 分钟"为持久层与循环优化前的历史记录；机器有空载波动时
  同配置耗时可在 34~63s 间摆动，性能对比须同窗口连测多次**
- **披露纪元缓存（2026-08-31，收益有限如实记录）**：财报视图按"披露纪元"缓存（键 =
  窗口报告期元组 + <=D 的最大披露边界，见 market_data `_fina_view_key`/`_attr_view_with_key`；
  其中 fina/bs/express 三个 per_stock 合并只依赖窗口、同窗口全部日期共享，这部分是稳定收益）。
  **实测发现**：Tushare 对旧报告期的修订会把 ann_date 回填到近期，披露边界全年密集——92 天
  回放窗口纪元共享率仅 ~8%（对照窗口 ~1%），纪元层近乎逐日重建；首查净收益 ~10% 且易被机器
  噪声掩盖。输出锚点与改前完全一致（数值列 + 成分多重集 + 序列末值分毫不差）。
  若需进一步压首查，正确方向是事件增量回放（按披露事件只更新受影响股票），未实施
- **持久缓存** `data/valuation_history.json`（本地运行产物，已 gitignore 不随仓库提交）：`{index_code: {"pe"/"pb": {日期: 值|null},
  "updated"}}`，逐日落盘（中断不丢已算日期），`version` 为算法版本号——**口径/公式/窗口右端规则
  任何变更必须 +1**（旧文件整文件作废重算）；窗口外旧日期保留无害（前端按 K 线日期对齐裁剪）
- **后台计算 `ValuationSeriesManager`**：**全局互斥串行**（不走单 worker 任务队列——分钟级计算会
  堵死榜单查询；跨指数并发只会对同一批日期重复发请求，串行化后第二只指数秒级），同指数重复
  start 幂等；前端"查询估值"按钮触发 → 进度轮询（`计算估值 x/y`）→ 就绪自动出图；弹窗关闭任务
  继续、重开按缓存即时渲染；**无渐进式推送**（2026-08-31 定稿不做，进度文本提示可关闭窗口）
- **入口约束**：仅**有官方行情的行业指数**（与 K 线同一 `sw_daily` 白名单，`web/service.
  _check_valuation_index`），个股 K 线隐藏 PE/PB 选项；CLI `python shenwan_industry/valuation_series.py
  <指数代码> [--window-days N] [--force]`（首查/增量/体检，`--force` 清该指数缓存重算）
